# Тестирование системы

## Обзор

Система включает комплексный набор тестов для проверки всех компонентов и сценариев использования.

## Доступные тесты

### 1. `test_all.php` - Главный тестовый файл
**Запуск:** `php test_all.php`

Запускает все доступные тесты и предоставляет общий отчет о состоянии системы.

**Что проверяет:**
- Все компоненты системы
- Интеграцию между модулями
- Производительность
- Обработку ошибок

### 2. `test_comprehensive.php` - Комплексное тестирование
**Запуск:** `php test_comprehensive.php`

Проверяет все компоненты системы по отдельности.

**Что проверяет:**
- ✅ Зависимости и файлы
- ✅ Конфигурацию
- ✅ API подключение
- ✅ Функции извлечения ID проекта
- ✅ Функции тарифов
- ✅ Маппинг должностей
- ✅ Получение компаний
- ✅ Получение задач проекта
- ✅ Анализ времени
- ✅ UF поля CRM
- ✅ Генерацию документов
- ✅ Настройки уведомлений
- ✅ Производительность

### 3. `test_scenarios.php` - Тестирование сценариев
**Запуск:** `php test_scenarios.php`

Проверяет реальные сценарии использования системы.

**Что проверяет:**
- 🔄 Полный цикл создания сделки
- 🔄 Обработку ошибок
- 🔄 Различные типы проектов
- 🔄 Производительность
- 🔄 Генерацию документов
- 🔄 UF поля и настройки

### 4. `test_functions.php` - Тестирование функций
**Запуск:** `php test_functions.php`

Проверяет корректность работы отдельных функций и методов.

**Что проверяет:**
- 🔧 Функции конфигурации
- 🔧 Методы DealCreator
- 🔧 Методы ProjectCheck
- 🔧 Методы DocumentGenerator
- 🔧 Методы UF_CRM_FieldChecker
- 🔧 Функции задержки
- 🔧 Константы конфигурации
- 🔧 Интеграционные тесты

### 5. `test_deal_creation.php` - Тестирование создания сделок
**Запуск:** `php test_deal_creation.php`

Специализированный тест для проверки создания сделок.

**Что проверяет:**
- 📊 Получение данных о времени
- 📊 Расчет стоимости
- 📊 Создание сделок
- 📊 Логирование

### 6. `test_combined_roles.php` - Тестирование ролей
**Запуск:** `php test_combined_roles.php`

Проверяет систему ролей и маппинг должностей.

**Что проверяет:**
- 👥 Маппинг должностей на роли
- 👥 Функции тарифов
- 👥 Нумерацию ролей

## Интерпретация результатов

### Цветовая индикация
- ✅ **Зеленый** - Тест пройден успешно
- ❌ **Красный** - Тест провален
- ⚠️ **Желтый** - Предупреждение
- ℹ️ **Синий** - Информация

### Процент успеха
- **90-100%** - Система готова к продакшену
- **70-89%** - Система работает с предупреждениями
- **50-69%** - Система требует доработки
- **0-49%** - Система не готова к использованию

## Логирование

Все тесты сохраняют подробные логи в папке `logs/`:

- `logs/comprehensive_test.log` - Комплексное тестирование
- `logs/scenarios_test.log` - Тестирование сценариев
- `logs/functions_test.log` - Тестирование функций
- `logs/deal_creation_test.log` - Создание сделок
- `logs/error.log` - Общие ошибки

## Настройка тестирования

### Переменные окружения
Убедитесь, что настроены:
- `BITRIX24_WEBHOOK_URL` в `set.php`
- Все константы в `config.php`
- UF поля в Bitrix24

### Права доступа
Убедитесь, что webhook имеет права на:
- `crm` (управление CRM)
- `tasks` (управление задачами)
- `user` (получение пользователей)
- `documentgenerator` (генерация документов)

## Устранение неполадок

### Частые проблемы

#### 1. Ошибки API
```
❌ API подключение не работает
```
**Решение:**
- Проверьте `BITRIX24_WEBHOOK_URL` в `set.php`
- Убедитесь, что webhook активен
- Проверьте права доступа webhook

#### 2. Отсутствуют UF поля
```
❌ UF поле не найдено
```
**Решение:**
- Запустите `php check_uf_crm_company_fields.php --all`
- Создайте недостающие поля в Bitrix24

#### 3. Нет данных для тестирования
```
⚠️ Нет компаний с проектами
```
**Решение:**
- Создайте компании с заполненным полем `UF_CRM_PROJECT_LINK`
- Убедитесь, что есть задачи в проектах

#### 4. Медленная работа
```
⚠️ Время выполнения превышает ожидаемое
```
**Решение:**
- Проверьте настройки `API_DELAY_BETWEEN_CALLS`
- Увеличьте `API_TIMEOUT`
- Проверьте скорость интернет-соединения

## Автоматизация тестирования

### Cron для регулярного тестирования
```crontab
# Ежедневное тестирование в 2:00
0 2 * * * cd /path/to/project-handler && php test_all.php >> logs/daily_test.log 2>&1

# Еженедельное полное тестирование в воскресенье в 3:00
0 3 * * 0 cd /path/to/project-handler && php test_comprehensive.php >> logs/weekly_test.log 2>&1
```

### CI/CD интеграция
```bash

# Скрипт для CI/CD
cd /path/to/project-handler

    echo "Все тесты пройдены"
    exit 0
else
    echo "Некоторые тесты провалены"
    exit 1
fi
```

## Расширение тестирования

### Добавление новых тестов

1. Создайте новый файл `test_custom.php`
2. Используйте стандартную структуру:
```php
<?php
// Подключение классов
require_once 'set.php';
// ... другие require

// Инициализация
$call = new Usual(BITRIX24_WEBHOOK_URL);
$logger = new Logger('custom_test.log', __DIR__ . '/logs');

// Ваши тесты
printTest("Мой тест", $success, "Детали");
?>
```

3. Добавьте в `test_all.php`:
```php
'test_custom.php' => 'Мой кастомный тест'
```

### Кастомные проверки

```php
// Пример кастомной проверки
function testCustomFunction() {
    $result = myCustomFunction();
    $expected = 'expected_value';
    $success = $result === $expected;
    
    printTest("Кастомная функция", $success, 
        "Получено: $result, ожидалось: $expected");
    
    return $success;
}
```
