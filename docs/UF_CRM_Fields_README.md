# Управление пользовательскими полями UF_CRM в компаниях Битрикс24

Этот набор скриптов предназначен для проверки и создания пользовательских полей UF_CRM в компаниях Битрикс24.

Все затраченное время в задаче засчитывается роли исполнителя задачи. Тарифы берутся для роли исполнителя, а не для роли того, кто логировал время.

## Файлы

- `UF_CRM_FieldChecker.php` - Основной класс для работы с пользовательскими полями
- `check_uf_crm_company_fields.php` - Универсальный скрипт для проверки и создания полей в компаниях
- `check_project_link_field.php` - Быстрая проверка поля UF_CRM_PROJECT_LINK в компаниях
- `web_check_fields.php` - Веб-интерфейс для работы через браузер
- `index_fields.php` - Главная страница веб-интерфейса

## Настройка

1. **Обновите webhook URL** в скриптах:
   ```php
   $webhook = 'https://akvilon-marketing.bitrix24.ru/rest/1/YOUR_WEBHOOK_CODE/';
   ```

2. **Убедитесь, что у вас есть права** на создание пользовательских полей в CRM

## Использование

### Проверка конкретного поля

```bash
php check_uf_crm_company_fields.php --field=UF_CRM_PROJECT_LINK
```

```bash
php check_uf_crm_company_fields.php --all
```

### Просмотр всех полей компаний

### Быстрая проверка поля UF_CRM_PROJECT_LINK

## API методы Битрикс24

Веб-интерфейс поддерживает работу с API методами Битрикс24 для получения информации о пользовательских полях:

### userfieldconfig.getTypes

Получает список доступных типов пользовательских полей для модуля.

**Параметры:**
- `moduleId` (string) - ID модуля (например, "crm", "iblock")

**Использование:**
```
http://your-domain.com/web_check_fields.php?action=types
```

### userfieldconfig.list

Получает список конфигураций пользовательских полей для модуля.

**Параметры:**
- `moduleId` (string) - ID модуля (обязательный)
- `select` (object) - Поля для выборки (опционально)
- `order` (object) - Сортировка (опционально)
- `filter` (object) - Фильтрация (опционально)
- `start` (number) - Начальная позиция (по умолчанию 0)

**Использование:**
```
http://your-domain.com/web_check_fields.php?action=configs
```

## Поддерживаемые поля

Скрипт автоматически проверяет и создает следующие поля:

| Код поля | Название | Тип | Описание |
|----------|----------|-----|----------|
| `UF_CRM_PROJECT_LINK` | Ссылка на проект | string | Ссылка на проект в Битрикс24 или ID проекта |
| `UF_CRM_ORIGINAL_DEAL` | Исходная сделка | string | ID исходной сделки для отслеживания связи |
| `UF_CRM_EXTRANET_USER` | Пользователь экстранета | user | Привязка к пользователю для уведомлений |
| `UF_CRM_HOURS_LIMIT` | Лимит часов | double | Максимальное количество часов для проекта |
| `UF_CRM_NOTIFY_DATE` | Дата уведомления | date | Дата последнего уведомления о превышении лимита |
| `UF_CRM_FRONTEND_RATE` | Цена за час - Front-end разработчик | money | Стоимость часа работы Front-end разработчика в рублях |
| `UF_CRM_BACKEND_RATE` | Цена за час - Back-end разработчик | money | Стоимость часа работы Back-end разработчика в рублях |
| `UF_CRM_DESIGNER_RATE` | Цена за час - Дизайнер | money | Стоимость часа работы Дизайнера в рублях |
| `UF_CRM_PM_RATE` | Цена за час - Проект-менеджер | money | Стоимость часа работы Проект-менеджера в рублях |
| `UF_CRM_CONTENT_MANAGER_RATE` | Цена за час - Контент-менеджер | money | Стоимость часа работы Контент-менеджера в рублях |

**Все поля создаются в сущности "Компании" (COMPANY)**

## Поддерживаемые типы полей

Скрипт поддерживает следующие типы полей:

- **string** - Текстовое поле
- **double** - Числовое поле с плавающей точкой
- **date** - Поле даты
- **user** - Привязка к пользователю (выпадающий список пользователей)
- **money** - Денежное поле (в рублях)

## Особенности поля UF_CRM_PROJECT_LINK

Поле `UF_CRM_PROJECT_LINK` создается как **текстовое поле** со следующими характеристиками:

- **Тип**: string (текстовое поле)
- **Размер**: 50 символов
- **Максимальная длина**: 255 символов
- **Обязательное**: Нет
- **Поиск**: Включен
- **Фильтр**: Включен
- **Справка**: "Ссылка на проект в Битрикс24 или ID проекта"

## Особенности поля UF_CRM_EXTRANET_USER

Поле `UF_CRM_EXTRANET_USER` создается как **привязка к пользователю** со следующими характеристиками:

- **Тип**: user (привязка к пользователю)
- **Отображение**: Выпадающий список
- **Высота списка**: 1 элемент
- **Максимальное количество**: 1 пользователь
- **Минимальное количество**: 1 пользователь
- **Не обязательное** для заполнения
- **Поддерживает поиск и фильтрацию**
- **Содержит справочную информацию**

## Особенности денежных полей

Денежные поля (тип `money`) создаются со следующими характеристиками:

- **Тип**: money (денежное поле)
- **Валюта**: RUB (российские рубли)
- **Формат**: Автоматическое форматирование с разделителями тысяч
- **Не обязательные** для заполнения
- **Поддерживают поиск и фильтрацию**
- **Содержат справочную информацию**

### Денежные поля для тарифов:

| Поле | Описание |
|------|----------|
| `UF_CRM_FRONTEND_RATE` | Тариф за час для Front-end разработчика |
| `UF_CRM_BACKEND_RATE` | Тариф за час для Back-end разработчика |
| `UF_CRM_DESIGNER_RATE` | Тариф за час для Дизайнера |
| `UF_CRM_PM_RATE` | Тариф за час для Проект-менеджера |
| `UF_CRM_CONTENT_MANAGER_RATE` | Тариф за час для Контент-менеджера |

**Важно:** Тарифы применяются к роли исполнителя задачи (RESPONSIBLE_ID), а не к роли того, кто логировал время. Это означает, что если задача назначена на Front-end разработчика, то время будет рассчитано по тарифу `UF_CRM_FRONTEND_RATE`, независимо от того, кто фактически логировал время.

## Логирование

Все операции логируются в файлы логов с помощью класса `Logger`. Логи включают:

- Проверку существования полей
- Создание новых полей
- Ошибки при работе с API
- Детальную информацию о результатах операций

## Обработка ошибок

Скрипты обрабатывают следующие типы ошибок:

- Ошибки подключения к API Битрикс24
- Ошибки валидации данных
- Ошибки создания полей
- Ошибки прав доступа

## Интеграция с существующим кодом

Класс `UF_CRM_FieldChecker` можно использовать в других частях системы:

```php
require_once 'UF_CRM_FieldChecker.php';

$fieldChecker = new UF_CRM_FieldChecker($call, $logger);

// Проверить существование поля
if ($fieldChecker->checkFieldExists('UF_CRM_PROJECT_LINK')) {
    // Поле существует
}

// Создать поле
$result = $fieldChecker->createProjectLinkField();
```
